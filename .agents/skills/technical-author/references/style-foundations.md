# Style foundations

These sources informed the skill's defaults. Project-specific terminology and user instructions take precedence.

- [Google developer documentation style guide](https://developers.google.com/style): clarity, consistent terminology, audience focus, accessible content, and guidance for global readers.
- [Microsoft Writing Style Guide](https://learn.microsoft.com/style-guide/): warm and relaxed voice, concise wording, everyday language, and action-oriented instructions.
- [Microsoft Learn style and voice quick start](https://learn.microsoft.com/en-us/contribute/content/style-quick-start): write for the reader's intent, make content scannable, and account for localization.
- [Write the Docs software documentation guide](https://www.writethedocs.org/guide/): practical documentation workflows and reader-centered structure.

Use these as principles, not as a license to copy wording or to override product-specific requirements. When sources disagree, favor the project's terminology and the clearest wording for the actual audience.
