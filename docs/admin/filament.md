# Filament control panel

The project has a second admin surface at `/control`. It is implemented with Filament 5 and runs alongside the legacy Inertia/Vue panel at `/admin` and `/portfolio`.

## Access

Open `/control/login` and use an existing application user. In local development all authenticated users can enter the panel. Outside local, access is limited to the comma-separated addresses in `FILAMENT_ADMIN_EMAILS`.

### Granting access on a test or production server

Add the administrator's email to the server's shared `.env` file. Keep this value
outside the repository; deployments restore the existing server `.env` after the
release is activated.

```bash
cd /home/<account>/htdocs/<site>
printf '\nFILAMENT_ADMIN_EMAILS=<admin-email>\n' >> .env
php8.3 current/artisan optimize:clear
php8.3 current/artisan tinker --execute='dump(config("filament.admin_emails"));'
```

If `FILAMENT_ADMIN_EMAILS` already exists, replace its value instead of adding a
second line. Multiple administrators are separated by commas:

```dotenv
FILAMENT_ADMIN_EMAILS=admin-one@example.com,admin-two@example.com
```

The allowlist is read through `config/filament.php`. After changing `.env`,
`optimize:clear` is required when configuration was cached; otherwise the old
empty allowlist remains active and a successful login is followed by a `403` at
`/control`. The authenticated user must also match an existing application user.

The panel uses the same session authentication as the application. A user must be authenticated before any resource route is available.

## Resource map

| Area | URL | Notes |
| --- | --- | --- |
| Pages | `/control/pages` | Page content, menu link and attached widgets |
| Posts | `/control/posts` | Category, status, content, SEO data and MinIO image URL |
| Categories | `/control/categories` | Slug is generated from the name; post count is shown |
| Services | `/control/services` | Service category, status, SEO fields and public upload image |
| Service categories | `/control/service-categories` | Slug is generated by the model from the name |
| Products | `/control/products` | Product details and many-to-many service selection |
| Product service styles | `/control/product-services` | CSS classes for product/service combinations |
| Widgets | `/control/widgets` | Widget category, rich content and MinIO image URL |
| Widget icons | `/control/widget-icons` | Icon class, description, URL and parent widget |
| Blog banners | `/control/blog-post-banners` | Banner metadata and `public/banners` image |
| Header bar | `/control/header-nav-bar-contents` | Top bar and social links |
| Footer bar | `/control/footer-bottom-bar-contents` | Footer company, FAQ and support links |
| Footer links | `/control/footer-useful-links` | Name, URL, status and position |
| Menus | `/control/menus` | Menu records and nested menu items |
| Menu items | `/control/menu-items` | Public page links and slugs |

Portfolio resources are also available under `/control` for education, skills, sections, subcategories, places and section items. Their forms preserve the existing `en`, `ua` and `pl` locale records and relationships.

## Storage rules

The upload targets match the legacy controllers:

- posts and widgets use the configured `s3` disk and store an absolute object URL;
- services use the `service_images` disk backed by `public/uploads` and store a filename;
- blog banners use the `banner_images` disk backed by `public/banners` and store a public path.

Do not replace these disks with the default local disk without updating the corresponding model accessor and deployment backup rules.

## Legacy boundary

The Vue panel remains available. Its routes and components are not removed while the Filament resources are rolled out. Filament resources own the records listed above; old Vue routes remain useful for features that have not yet been represented as a Filament resource.

When adding or changing a resource, compare its form with the matching Vue component and request class. Preserve slug generation, relationship fields, validation and image storage behavior before enabling destructive actions.

## Verification

Run the checks from the application container:

```bash
vendor/bin/pint --test
vendor/bin/phpunit --no-coverage
php artisan route:list --path=control
```

Authenticated smoke checks should cover the dashboard, every resource index and every create form. A `403` on Posts or Categories usually means their policy does not allow the Filament panel or the record owner.
